# ProPainter 残留窗口全片优先调度

## 背景

STTN 残留转交 ProPainter 的 `sttn_residual_propainter_max_windows` 当前按
视频时间顺序消耗预算。设置最多 8 个窗口时，前 8 个候选会占用全部预算，
后面更严重的残留无法获得 ProPainter 修复。

## 目标

- 当设置了正数的 `sttn_residual_propainter_max_windows` 时，从整条视频的全部
  合格候选中选择最需要 ProPainter 的 Top-K 窗口。
- 第一排序指标是截短后的残留核心帧数；第二排序指标是窗口内残留像素总量；
  两项都相同时选择时间更早的窗口。
- 保留候选窗口原有的上下文、`max_frames` 截短规则、最小核心帧过滤和场景边界。
- ProPainter 处理和最终输出仍按时间顺序写回；未选中的窗口保留 STTN 结果。
- `max_windows=0` 的不限预算路径继续使用现有流式处理，不引入额外的视频遍历。

## 实现方案

有正数窗口预算时，STTN 第一遍仍按当前逻辑推理并写出中间视频，同时记录每个
合格候选的时间范围、上下文帧、逐帧框、残留核心帧和严重度分数。候选收集完成后，
按 `(-core_frames, -residual_pixels, start_frame)` 排序并截取 Top-K。第二遍读取
中间视频和源视频，在选中窗口上调用 ProPainter；只把残留核心帧的修复结果写回，
上下文帧和其他帧保持第一遍结果。中间视频使用无损编码，避免第二遍处理造成额外
有损压缩；最终视频仍使用现有 CRF 设置。

选中窗口的统计在第二遍调用时更新，残留计数根据 ProPainter 结果重新校正。未选中
窗口的统计保持第一遍 STTN 结果。若 ProPainter 调用失败，沿用现有异常处理语义，
不静默丢弃选中窗口。

## 测试

- 增加跨多个 STTN 段的回归测试：后出现但残留核心帧更多的窗口应优先于前面的窗口。
- 验证相同核心帧数时按残留像素总量和时间顺序稳定决胜。
- 验证 `max_windows=0` 和候选少于预算时保持现有调用数量与输出契约。
- 运行 STTN 流水线回归、窗口跟踪测试和 `git diff --check`。
