# 连续切景边界的字幕命中保留

状态：用户已确认书面设计，进入实施与验证；本轮不提交或推送。

## 问题与目标

`test_pro_19.mp4` 在第 665-667 帧（从 0 计数，22.167-22.267 秒）
出现两行完整字幕闪回。原片在这三帧都有两行 OCR 命中，但当前切景判断
将 665、666、667、668 连续四帧标为新镜头。前面三帧因此各自成为
单帧轨迹，被至少两次命中的规则过滤，最终字幕遮罩为零。

使用 `-c 450 1010 0 720` 和真实本地 OCR 已重复重放该问题。
18 的相同三帧也有闪回；14 没有这次整句闪回。

目标是恢复这些被误过滤的真实字幕命中，同时保持人物、背景和真实切景
的保护。不承诺本次解决句末点号、开头 emoji 细边或其他局部残字。

## 方案选择

1. 采用：以相邻原始 OCR 观测的文字内容为单帧轨迹补充确认依据。
   不改变切景列表，只恢复有明确字形证据的当前帧检测框。
2. 不采用：全局降低 `min_hits` 为 1。会让无相邻支持的孤立误检进入修复。
3. 不采用：直接提高切景阈值或取消切景分段。不能保证其他素材的真实切景
   仍被正确识别，也会影响 ProPainter 的图像上下文。

## 数据流与模块职责

- `vsr_pipeline.py`：保留现有反馈式 OCR 调度，在已有检测观测之间核验
  跨切景的字幕连续性。核验只使用相邻采样及已有回查产生的原始图像、
  原始 OCR 框和原始字形遮罩；不发起额外 OCR 或网络调用。
- `backend/subtitle_templates.py`：复用现有位置、边缘、局部对比度及
  字形核心的一致性核验，提供有界的观测匹配能力。不得降低现有阈值，
  不将整行矩形作为可信字形，也不让补全生成的字形反过来成为确认依据。
- `backend/subtitle_tracking.py`：接收明确到帧号和检测框的确认依据。
  普通轨迹继续执行至少两次命中；不足两次的轨迹只有包含内容已确认的
  当前观测才可保留。无确认依据的旧调用保持原行为。
- 轨迹仍按原切景边界独立建立，不因确认依据而跨镜头插值。后续
  ProPainter 分段、字形补全、合成及残留复核沿用现有流程。

## 安全边界

- 候选必须跨越已有切景边界，且观测间隔不超过当前最大 OCR 采样步长。
  已有回查观测按时间顺序参与核验，不能越过已检测为空或文字不同的观测。
- 必须有当前帧真实 OCR 框。只共享“该命中可信”的依据，不复制旧框到
  无命中的帧，不从旧图像复制修复像素。
- 两个观测均须核验完整可用字形，防止相同前缀、不同后缀或缩短的 OCR
  框错误授权另一整行内容。多行字幕逐行确认，不能一行匹配就放行全部框。
- 只保留相邻观测所需的图像或局部参考，不缓存整片图像。后续长期字形
  缓存继续遵守 64 条及 60 帧限制。
- 无可靠字形、内容不符、字幕消失、孤立误检或过期观测均不授予额外确认。
  检测总数、接受总数及丢弃总数应与最终轨迹一致。
- ROI、白色大物体过滤、有效遮罩外像素保护、模型和复修上限不变。

## 验收

1. 先新增失败回归：连续三个单帧切景中，内容相同的两行字幕必须保留；
   无确认依据的单次误检仍丢弃；多行只恢复内容得到支持的那一行。
2. 内容反例覆盖换字、相似字母、同前缀不同后缀、字幕消失、空 OCR、
   不匹配的中间观测及超出间隔。保持稳定字幕逐渐跳帧及 OCR 调用数不变。
3. 通过真实 `process_video` 路径验证恢复后的框和遮罩到达修复引擎，
   各模型窗口仍不跨切景，帧数、时间戳及 ROI 外像素保护不退化。
   单元和集成测试仅以替身替代 OCR 推理及 GPU 修复模型。
4. 使用原片和已缓存的真实 OCR 重放第 650-686 帧，确认 665-667 每帧
   两行框不再被过滤且字幕遮罩非零。真实素材作为可选回归输入，不上传视频。
5. 运行全量测试、语法编译和差异检查。服务器继续同一 ROI 生成新文件
   `test_pro_20.mp4` 验收最终画质，不覆盖 19。

本机的轨迹与遮罩回归通过不等于 CUDA 成片已擦净；最终交付须明确区分。
