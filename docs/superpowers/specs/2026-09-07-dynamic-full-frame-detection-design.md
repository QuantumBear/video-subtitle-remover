# 动态全屏检测与保守双层遮罩设计

## 1. 背景与问题

当前流水线的 `-c YMIN YMAX XMIN XMAX` 同时限制 OCR、DashScope 贴纸定位和白字自检。未指定 `-c` 时，代码先在稀疏采样帧上生成一个“字幕活动带”的整体矩形，再在这个矩形内逐帧检测。

这个策略有两个根本限制：

1. 字幕可能在不同时间出现在多个不相邻位置，整体并集框会漏掉区域或扩大到大量背景。
2. 最近的 ProPainter 优化将横向白字幕从整行矩形改为严格白字形遮罩，减轻了 4–5 秒场景的背景误擦，但抗锯齿边缘、灰色描边和低对比度笔画可能没有进入遮罩，造成残留。ProPainter 分支也没有 LAMA 分支中的局部残留复核。
3. 0–2 秒的三个小 emoji 尺寸很小；当前 DashScope 只在 OCR 命中区间抽样，且要求贴纸在多个采样帧中稳定出现，单帧或早期命中容易被过滤。

目标是在不传 `-c` 时支持字幕/贴纸在画面任意位置移动，同时优先减少误擦；指定 `-c` 时仍保留手动 ROI 作为性能和误检控制手段。

## 2. 目标与非目标

### 目标

- 默认模式对每一帧执行全屏 OCR，输出全帧坐标的候选文字框。
- 通过时间连续性、空间移动限制和字幕形态过滤，将候选框组织成字幕轨迹，而不是生成一个全局并集框。
- 对白字幕采用“字形核心 + 窄边缘”的双层遮罩：覆盖抗锯齿和描边，但保留字间背景、人物和物体轮廓。
- 对 emoji/贴纸使用 DashScope 做全屏稀疏采样，并通过字幕轨迹邻近关系和时间连续性抑制真实物体误检。
- 对 ProPainter 输出进行一次受限的局部残留复核，只在原文字轨迹内追加修复。
- 保持 24GB 显存配置（60 帧输入窗口）和现有音频合并、PTS、无 B 帧输出行为。
- 保持现有手动 `-c` 命令兼容。

### 非目标

- 不承诺识别所有语言、艺术字体或极低对比度字幕；无法识别的内容允许少量漏检。
- 不把视频中所有真实文字（车身、衣服、路牌等）当作字幕删除。
- 不在本次工作中更换 PaddleOCR、DashScope 或 ProPainter 模型。
- 不把整帧或长时间大矩形交给 ProPainter 作为默认遮罩。

## 3. 方案比较与选择

### 方案 A：继续使用更精确的固定 `-c`

实现最简单，能减少 OCR 搜索范围和误检，但无法覆盖字幕跨区域移动，也无法解决白字形遮罩过窄和早期 emoji 被过滤的问题。仅作为手动兜底，不作为默认方案。

### 方案 B：无框时自动生成一个更大的整体矩形

比当前活动带更不容易漏检，但会把多个场景的位置并成一个大框，增加 OCR 误检和 VLM 误检，且无法控制 ProPainter 对移动背景的影响。放弃。

### 方案 C：动态全屏检测 + 保守双层遮罩（选定）

逐帧全屏 OCR 提供候选框，轨迹层负责时序过滤和补齐短暂漏检；贴纸层独立采样并与字幕轨迹关联；遮罩层区分白字、彩色文字和贴纸；ProPainter 后处理只处理局部残留。它直接针对当前两类残留，同时保留误擦保护能力。

## 4. 运行模式与参数语义

### 无 `-c`（默认自动模式）

- `region` 设为整帧 `(0, H, 0, W)`。
- OCR 在整帧上运行，检测框始终转换为全帧坐标。
- 不再依赖 `auto_region()` 生成单个整体矩形；该函数可保留用于兼容性或后续显式优化，但不能决定检测范围。
- DashScope 采样使用整帧图像，避免字幕/贴纸移出先前活动带后被裁掉。

### 指定 `-c YMIN YMAX XMIN XMAX`

- 继续将该矩形作为 OCR 和 DashScope 的 ROI。
- ROI 外不检测、不创建遮罩，适合用户已知字幕范围且希望降低耗时/误检的场景。
- 日志必须明确显示当前是 `full-frame` 还是手动 ROI，避免用户误以为自动模式仍使用旧活动带。

## 5. 检测与时序轨迹

### 5.1 OCR 候选框

保留现有宽高比过滤，但把每帧候选框统一保存为全帧坐标，并保留帧号、宽高、可用的 OCR 置信度（模型未提供时使用几何特征）。单帧候选不直接进入 ProPainter。

### 5.2 字幕轨迹

新增独立的轨迹层，输入逐帧候选框，输出逐帧字幕框：

- 用垂直/水平重叠、中心距离和尺寸变化匹配相邻帧候选；允许字幕缓慢移动和短暂漏检。
- 轨迹必须满足最小命中数或最小持续时间；孤立的一帧候选默认丢弃。
- 对轨迹内部的短间隙使用最近邻框补齐，但不使用整个轨迹的空间并集，避免移动字幕把整条移动带都变成空洞。
- 多行字幕保持独立框，只有在时间和空间都连续时才合并为同一轨迹组。

现有 `filter_boxes_by_continuity()` 和 `expand_timeline()` 的原则可以复用，但实现应从“全局候选列表”提升为“轨迹级状态”，以支持同一视频内多个不相邻字幕区域。

## 6. DashScope 贴纸/emoji 定位

### 6.1 采样

- 自动模式在整帧上按固定时间步长稀疏采样，并额外覆盖每条字幕轨迹的起始、结束和中间帧。
- 手动 ROI 模式沿用 ROI 裁剪。
- 采样步长、请求模型和超时保持可配置；默认不因每帧调用 VLM 而显著增加成本。

### 6.2 过滤与传播

- 提示词继续要求只返回 emoji/贴纸/图案水印，不返回真实物体和文字。
- 稳定贴纸默认要求至少两个时间点命中；但“单次命中 + 紧邻已确认字幕轨迹”允许只在短时间窗口内传播，以覆盖 0–2 秒的小 emoji。
- 贴纸框必须与字幕轨迹在时间上相邻、空间上接近（阈值配置化）；远离字幕轨迹的单帧命中丢弃。
- 相邻 emoji 保持独立轨迹，不能因为框相交或距离近而合并。
- DashScope 未配置、请求失败或返回非法 JSON 时只跳过贴纸层，OCR 字幕处理继续，命令不失败。

## 7. 保守双层遮罩

### 7.1 白色横向字幕

在每个字幕框内生成：

1. `core_mask`：现有高置信白字形，用于覆盖笔画主体。
2. `edge_mask`：较宽松的亮度/颜色判据，仅在 `core_mask` 或 OCR 框内部附近生效，再做小半径形态学膨胀（默认 2–4 px）。

最终白字幕遮罩为两层并集，不填充整行矩形。大块白色衣物、车身和地面高光需通过连通域高度/面积和字幕框邻域限制排除。

阈值和膨胀半径集中为常量，便于根据服务器输出调整；不得把“扩大整行矩形”作为补残留手段。

### 7.2 彩色文字和贴纸

- 无法可靠提取字形的彩色字幕使用 OCR 框矩形，但只在框内加入小边缘扩展。
- VLM 贴纸使用独立的贴纸外扩值；相邻贴纸仍按独立框处理。

### 7.3 ProPainter 局部残留复核

第一轮 ProPainter 输出后，只在原字幕轨迹内部计算白字残留：

- 残留低于阈值视为压缩噪声，不再处理。
- 超过阈值时生成局部 `repair_mask`，只对包含残留的短窗口追加一次 ProPainter 修复；窗口带少量前后文，但不重新处理全片。
- 第二轮输出只覆盖 `repair_mask` 膨胀后的窄区域，其他像素严格保留第一轮结果。
- 每个窗口最多追加一次；若显存不足或模型调用失败，保留第一轮结果并记录警告，不能导致整条视频失败。

## 8. 数据流与模块边界

```text
输入视频
  │
  ├─ ROI 选择：无 -c=整帧；有 -c=用户 ROI
  │
  ├─ 第一遍 OCR：逐帧候选框（全帧坐标）
  │       └─ 字幕轨迹：匹配、去孤立、短间隙补齐
  │
  ├─ DashScope：整帧/ROI 稀疏采样 → 贴纸轨迹 → 与字幕轨迹关联
  │
  ├─ 遮罩生成：白字双层 / 彩色框 / 贴纸框
  │
  ├─ ProPainter 分段修复（60 帧输入窗口）
  │       └─ 局部残留复核 → 一次受限二次修复
  │
  └─ 保留原音频、PTS 和帧数，写出 MP4
```

建议保持以下边界：

- `Pipeline.detect()` 只负责单帧候选检测，不负责跨帧决策。
- 新的轨迹组件只接收/输出框和帧号，不依赖 OCR、VLM 或 ProPainter。
- `locate_stickers_vlm()` 只负责定位贴纸候选，关联和传播由轨迹层决定。
- 遮罩组件只接收全帧图像、轨迹框和类型，输出逐帧 mask。
- ProPainter 调度器负责分段、显存保护和二次局部窗口，不修改检测规则。

## 9. 日志、失败处理与可观测性

每次处理至少输出：

- `detection-mode=full-frame` 或 `roi=(...)`；
- OCR 候选帧数、确认轨迹数、丢弃的孤立框数；
- DashScope 采样帧数、命中数、稳定轨迹数、因关联失败丢弃数；
- 第一轮修复帧数、残留复核帧数、第二轮局部修复窗口数；
- 关键时间段（首帧、0–2 秒、4–5 秒）可通过现有进度日志定位。

没有 OCR 命中时直接保留原帧；没有 DashScope 时只跳过贴纸层；单个 VLM 请求失败不影响后续采样；轨迹或二次修复异常必须降级为第一轮结果并继续输出。

## 10. 测试与验收

### 单元测试

- 全屏模式下，两个不相邻字幕区域能形成两条独立轨迹。
- 字幕移动时，轨迹补齐短暂漏检，但不会生成整个移动带并集。
- 孤立 OCR 框被丢弃，连续字幕框被保留。
- 双层白字遮罩覆盖低亮度抗锯齿边缘，同时保持字间背景为 0。
- 单帧 emoji 在字幕轨迹附近可进入短窗口；远离字幕的单帧真实物体命中被丢弃。
- 相邻多个 emoji 不被合并。
- `-c` 指定时只在 ROI 内工作，不指定时使用整帧。

### 回归/集成验收

使用当前 TikSave 输入视频，在 24GB GPU 上运行：

```bash
python vsr_pipeline.py \
  -i TikSave.io_7635080993354878239.mp4 \
  -o test_auto_dynamic.mp4 \
  --inpaint-mode propainter
```

验收重点：

1. 0–2 秒三个 emoji 无明显可见残留。
2. 4–5 秒字幕被去除，但楼梯、裤腿和车身不出现大块重绘/闪烁。
3. 不传 `-c` 与传入手动 ROI 都能完成处理；手动 ROI 仍可作为对照。
4. 输出帧数、时长和音频轨道与输入一致，显存不超过服务器可用上限。
5. 失败的 DashScope 请求和局部二次修复不会中断整条视频。

## 11. 分阶段实施顺序

1. 抽出轨迹数据结构和全屏默认模式，先用现有矩形遮罩验证检测覆盖范围。
2. 加入白字幕双层遮罩，并以 4–5 秒场景做误擦回归。
3. 调整 DashScope 全屏采样、字幕邻近关联和单帧短窗口例外，重点回归 0–2 秒 emoji。
4. 接入 ProPainter 局部残留复核和显存/失败降级。
5. 补齐单元测试、日志和命令行帮助文案，再运行完整回归。
