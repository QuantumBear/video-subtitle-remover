# 字幕去除总流程

这篇讲项目处理视频时，代码实际经过哪些步骤。

## 一张路线图

```text
CLI / API 调用
   |
   v
SubtitleRemover 初始化
   |
   +--> sttn-auto：调用方指定选区 -> 遮罩 -> STTN
   |
   +--> 其他模式：文本检测 -> 时间段 -> 遮罩 -> 修复模型
   |
   v
临时视频 -> 复制原音频 -> 最终输出
```

总控类是 `backend/main.py` 中的 `SubtitleRemover`。

## 第 1 步：选择输入和区域

调用方通过命令行参数或 API 请求提交视频或图片，并指定处理区域。

区域可以是一个或多个。如果传入的是比例坐标，真正开始处理时会转成原视频像素坐标。

如果没有选区，后端会把整个画面作为处理区域。这样自动检测可能会处理画面中的所有文字，而不只是字幕。

命令行和 API 还可以设置帧范围，只处理指定的帧区间。

## 第 2 步：初始化处理器

`SubtitleRemover.__init__()` 会读取：

- 视频宽、高、帧数和 FPS。
- OpenCV 视频读取器。
- 临时视频写入器。
- 模型路径和硬件加速设备。
- 默认输出路径和进度状态。

视频帧由 `FramePrefetcher` 在后台预读取，让解码和模型推理尽量重叠。

## 第 3 步：选择处理路线

### `sttn-auto`

不调用文本检测模型。程序把调用方指定的选区转换成遮罩，然后让 STTN 直接修复该区域的所有相关帧。

它适合字幕位置固定、选区容易指定准确的普通视频。

### `sttn-det`、`lama`、`opencv`

这些模式共用 `video_inpaint()`：

```text
文本检测 -> 文字框整理 -> 字幕时间段 -> 遮罩 -> 对应修复模型
```

### `propainter`

ProPainter 有单独的 `propainter_mode()`。它会先检测文字，再按文字时间段和场景切换切分视频块。

## 第 4 步：文本检测

`SubtitleDetect` 使用 PaddleOCR 文本检测模型，主要输出文字框，不识别文字内容。

为了节省时间，程序不会对每一帧做检测，而是根据 FPS 抽样：

- 30 FPS 以下：每 2 帧检测一次。
- 30～60 FPS：每 3 帧检测一次。
- 60 FPS 以上：每 4 帧检测一次。

采样结果之间距离较小时，程序会用前一个结果填充中间帧。因此这是速度和召回率之间的折中。

在 STTN_DET、LAMA 和 OpenCV 共用的 `video_inpaint()` 路线上，检测结果还会经过以下处理：

- 必须完全落在指定选区内。
- 相邻帧中位置相近的框会被统一。
- 过高、疑似误检的框可能被跳过。

## 第 5 步：生成时间段和遮罩

程序会把有文字框的帧合并成连续时间段，并在时间段前后扩展少量帧，减少字幕刚出现或刚消失时的漏处理。

`create_mask()` 会把文字框画成白色区域，并默认向外扩大 10 像素。

遮罩不是“删除区域”，而是告诉修复模型：这里的内容需要重新生成。

## 第 6 步：批量修复

字幕时间段内的帧会按批次读取。没有字幕的帧通常直接写回，不会送进模型。

不同模型的修复方式不同：

- STTN：利用邻近帧和参考帧。
- LAMA：逐帧根据空间纹理修复。
- ProPainter：利用光流和视频 Transformer。
- OpenCV：使用邻域插值。

部分辅助函数会把遮罩组织成较大的横向修复区域，因此实际写回范围可能大于文字框本身。

## 第 7 步：写出视频

修复后的帧先写入临时视频。

优先使用 `FFmpegVideoWriter` 和 `libx264` 编码；如果 FFmpeg 管道失败，才回退到 OpenCV 的 `mp4v`。

视频分辨率和帧率保持原值，但画面会重新编码，不是像素级无损输出。

## 第 8 步：合并原音频

画面处理完成后，程序从原视频提取音频流，再把音频复制到新视频。

如果音频提取或合并失败，程序会尝试保留没有音频的临时视频。

## 图片路线

图片只有一帧。处理图片时会使用 LAMA，流程是：

```text
读取图片 -> OCR 检测一次 -> 创建遮罩 -> LAMA 修复 -> 保存图片
```

图片输出路径取决于入口：如果调用方指定了输出路径则使用指定路径，未被覆盖输出路径时则会使用输入目录下的 `no_sub/` 文件夹。

## 最核心的理解

去字幕不是删除视频的一部分，而是：

```text
定位文字 -> 标记需要重建的区域 -> 利用图像或视频上下文补画面
```

最终效果首先取决于遮罩是否准确，其次才是修复模型本身。
