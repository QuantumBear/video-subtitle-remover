# 视频帧、文字框、遮罩、修复、音频

这篇把最重要的概念连起来，并说明它们在代码中的数据形状。

## 1. 视频帧

视频由很多张图片组成。

代码中常见变量：

```text
frame          当前帧，通常是 OpenCV 的 BGR 数组
frame_count    视频总帧数
frame_width    帧宽
frame_height   帧高
fps            每秒帧数
```

视频处理时，非字幕区间的帧可以直接写回；需要修复的区间会按批次送进模型。

## 2. 选区、文字框和坐标顺序

调用方指定的选区通常使用：

```text
(ymin, ymax, xmin, xmax)
```

文本检测结果经过 `ocr.py` 整理后，常用格式是：

```text
(xmin, xmax, ymin, ymax)
```

两种格式只是字段顺序不同。读代码时要看当前函数要求的顺序，不能直接混用。

OCR 原始结果是四边形点，当前实现会整理成矩形框。矩形框容易处理，但可能比真实文字轮廓更宽。

## 3. 遮罩

遮罩是一张和视频帧同样大小的黑白图：

- 白色或 1：需要修复。
- 黑色或 0：通常保留原画面。

`create_mask()` 会把文字框画成白色矩形，并默认扩大 `subtitleAreaDeviationPixel` 个像素。

扩大可以减少残字，但也会让模型修改更多背景。扩大值过大，是画面误伤的常见原因。

## 4. 修复区域和文字区域不是一回事

文字框是“检测到文字的范围”。

修复区域是“模型实际看到和写回的范围”，可能包含文字周围的上下文。

当前 `get_inpaint_area_by_mask()` 通常将修复区域设置为整幅宽度的横向带状区域。这样模型上下文更充分，但也可能扩大画面变化范围。

`STTN_AUTO` 会在最终合成时按 mask 融合；其他包装器可能先生成较大区域，再把整块结果写回，所以模式之间的误伤风险不同。

## 5. 修复模型

- `STTN_AUTO`：指定选区直接修复，不做 OCR。
- `STTN_DET`：OCR 找框，再用 STTN 修复视频。
- `LAMA`：逐帧进行图像修复，图片模式固定使用它。
- `PROPAINTER`：用光流和 Transformer 做视频修复。
- `OPENCV`：传统邻域插值，不使用前后帧。

STTN 和 ProPainter 会使用时间上下文，因此通常比逐帧方法更适合视频。

## 6. 音频

项目主要处理画面，不重新编码音频。

流程是：

1. 先生成只有画面的视频。
2. 从原视频提取音频流。
3. 使用 FFmpeg 将音频流复制回新视频。

如果音频处理失败，输出可能只有画面。

## 7. 一个完整例子

假设第 100～150 帧出现底部字幕：

1. 文本检测在若干采样帧中找到文字框。
2. 程序把检测结果整理成连续时间段。
3. 文字框被扩大并画成遮罩。
4. 修复模型读取这段帧和参考帧。
5. 输出没有字幕的新帧。
6. 非字幕帧直接写回，最后合并原音频。

## 你现在只需要记住

字幕去除不是把一块区域裁掉，而是：

```text
检测或指定区域 -> 生成遮罩 -> 根据上下文重建画面
```

如果遮罩过大，或者被字幕遮住的背景从未在其他帧出现，模型只能猜测，画面就可能被破坏。
