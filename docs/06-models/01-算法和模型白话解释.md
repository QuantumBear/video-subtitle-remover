# 算法和模型白话解释

这篇不讲论文，只讲项目中每类模型负责什么，以及应该怎么选。

## 先区分两类模型

项目里的模型大致分两类：

1. 文本检测模型：回答“哪里可能有文字”。
2. 画面修复模型：回答“被遮住的地方应该补成什么样”。

文本检测模型和修复模型不是一回事。

## 文本检测模型

文本检测使用 PaddleOCR 的检测模型：

- `PP_OCRv5_MOBILE`：更轻，通常更快。
- `PP_OCRv5_SERVER`：更重，通常有更强的检测能力。

代码主要读取文字框，不识别具体字幕内容，也不判断文字是字幕还是水印。

相关代码：

```text
backend/tools/subtitle_detect.py
backend/tools/model_config.py
backend/models/V5/
```

## STTN_AUTO

`sttn-auto` 是当前默认的修复模式。

它不做 OCR，而是直接使用调用方传入的区域作为遮罩，再用 STTN 根据邻近帧和参考帧进行视频修复。

适合：

- 字幕位置固定。
- 能准确指定字幕区域。
- 普通真人视频或运动不太剧烈的场景。

风险是选区太大时会误伤更多背景。

## STTN_DET

`sttn-det` 会先用文本检测模型找框，再调用 STTN 修复。

它比直接处理整块指定区域更有针对性，但会受到 OCR 漏检、抽样间隔和文字框大小的影响。

STTN 是视频模型，会使用时间上下文，因此通常比逐帧图像修复更适合连续视频。

## LAMA

LAMA 主要根据单帧中的空间纹理完成图像修复。

作为服务调用时，单张图片处理通常默认使用 LAMA。

适合：

- 图片。
- 动画或静态背景。
- 字幕遮挡区域较小的画面。

它没有专门的视频时间建模，连续帧之间可能出现轻微闪烁。

## ProPainter

ProPainter 是项目中最重的视频修复模型，但不是默认模式，也不是所有场景的最佳选择。

它大致经过：

```text
RAFT 光流 -> 光流补全 -> 背景传播 -> Transformer 修复
```

适合人物、物体或摄像机运动明显的场景。

优点：时间一致性和运动处理能力通常更强。

缺点：速度慢、显存占用高，而且遮罩过大时也可能破坏更多背景。

## OpenCV

OpenCV 模式调用传统 `cv2.inpaint()`。

它逐帧根据附近像素插值，不参考前后帧。

适合小面积、纯色或简单纹理背景。复杂运动和大面积遮挡通常不适合。

## 怎么选

可以先按下面的经验选择：

| 视频情况 | 优先尝试 |
|---|---|
| 固定位置的普通字幕 | `sttn-auto` |
| 希望 OCR 只处理文字框 | `sttn-det` |
| 图片或静态动画 | `lama` |
| 运动剧烈、背景变化明显 | `propainter` |
| 小块简单背景 | `opencv` |

如果结果有明显画面损坏，先检查选区和遮罩范围，再考虑更换模型。

## 模型文件在哪里

主要模型目录是：

```text
backend/models/
```

包括：

- `V5/`：文本检测模型。
- `sttn-auto/`：直接选区修复模型。
- `sttn-det/`：检测后修复模型。
- `big-lama/`：LAMA 模型。
- `propainter/`：ProPainter 和光流相关模型。

## 你现在只需要记住

OCR 负责“标出可能的文字区域”。

Inpaint 模型负责“根据画面上下文重建被遮挡区域”。

最终效果通常先取决于遮罩是否准确，再取决于模型是否适合当前视频。
