# 配置项怎么理解

这篇讲 `backend/config.py` 中和处理质量、速度最相关的配置。

## config.py 是什么

`backend/config.py` 是项目的配置中心。

它保存默认选区、修复模式、检测模型、批大小、硬件加速和输出目录等设置。

## `subtitleSelectionAreas`

这是默认处理选区，保存的是比例而不是像素。

默认值：

```text
0.88,0.99,0.15,0.85
```

它大致表示画面底部中间区域。API 接收请求后，处理前会把比例坐标转换成原视频像素坐标。

如果选区为空，运行时后端会回退到全屏区域。

## `inpaintMode`

这是画面修复模式，默认值是 `STTN_AUTO`。

可选值：

- `STTN_AUTO`：不做 OCR，直接修复指定选区。
- `STTN_DET`：OCR 检测后使用 STTN。
- `LAMA`：逐帧图像修复，图片模式固定使用。
- `PROPAINTER`：光流和视频 Transformer 修复。
- `OPENCV`：传统逐帧插值修复。

## `subtitleDetectMode`

这是文本检测模型，不是修复模型。

- `PP_OCRv5_MOBILE`：模型较轻，通常更快。
- `PP_OCRv5_SERVER`：模型较重，通常检测能力更强。

它们都主要找文字框，不判断文字是不是字幕。

## `subtitleAreaDeviationPixel`

这是文字框向外扩大的像素数，默认是 10。

扩大可以避免文字边缘残留，但也会扩大被模型修改的背景范围。

如果画面误伤明显，可以尝试调小；如果文字边缘残留，再逐步调大。

## `subtitleAreaYAxisDifferencePixel`

用于判断文字框高度关系，帮助把同一行文字归为相近区域。

它影响检测框的整理，不是直接控制最终遮罩大小。

## `subtitleAreaPixelToleranceXPixel` 和 `subtitleAreaPixelToleranceYPixel`

用于判断相邻检测结果是否可以视为同一个文字框。

值太小可能让一个字幕被分成很多段，值太大可能把不同位置的文字框错误合并。

## 字幕时间扩展

### `subtitleTimelineBackwardFrameCount`

检测到字幕出现后，额外向前处理多少帧。默认是 3。

### `subtitleTimelineForwardFrameCount`

检测到字幕消失后，额外向后处理多少帧。默认是 3。

它们可以减少漏处理，但也会让更多没有字幕的帧进入修复流程。画面误伤明显时，可以先降低到 0～1。

## STTN 参数

### `sttnNeighborStride`

处理视频时，邻近帧参考的步长。步长越小，参考帧更密集，但计算和显存开销可能增加。

### `sttnReferenceLength`

用于构造参考帧的间隔参数。值越大通常能提供更远的背景上下文，但也更慢、更占显存。

### `sttnMaxLoadNum`

STTN 一次最多加载多少帧。

值越大不一定始终更好；视频分辨率较高时，过大可能导致显存不足。程序会确保它不小于必要的参考范围。

## `propainterMaxLoadNum`

ProPainter 一次处理的视频帧上限。

值越大，时序上下文可能更充分，但显存和处理时间也会明显增加。

## `hardwareAcceleration`

是否允许项目使用硬件加速。

不同模式支持不同设备：STTN 可使用 CUDA、DirectML 或 MPS；LAMA 主要使用 CUDA 或 MPS；当前 ProPainter 路径主要使用 CUDA。

视频解码、OCR 的 CPU 部分和 FFmpeg 编码仍会消耗 CPU。

## `saveDirectory`

输出目录。为空时，默认把结果放在输入文件所在目录。

视频通常输出为：

```text
原文件名_no_sub.mp4
```

处理图片时，如果不指定路径，默认会放在输入目录下的 `no_sub/` 文件夹。

## 调参顺序建议

如果画面被误伤：

1. 先缩小处理选区。
2. 再减小 `subtitleAreaDeviationPixel`。
3. 再减少前后时间扩展帧数。
4. 最后再切换模型。

如果字幕残留：顺序相反，逐步扩大选区或遮罩，不要一次把所有参数调到最大。
