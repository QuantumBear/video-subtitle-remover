# 实战去字幕流程(本机验证版)

## 2026-09-10：默认轻度增强字形边缘

ProPainter 默认使用 `--subtitle-strength light`：在 26 版精确字形遮罩的
最后一道描边上增加 1px，半径从 2px 调至 3px。新增范围仍被对应文字框
和 ROI 裁剪，不做整行矩形擦除。模型输入与最终合成使用同一份有效遮罩；
编码前遮罩外的原图保持不变。

原命令无需增加参数，只换输出文件名以便对照：

```bash
python vsr_pipeline.py -i TikSave.io_7635080993354878239.mp4 \
  -o test_pro_27_without_c.mp4 --inpaint-mode propainter \
  --sticker-backend gdino \
  --sticker-model-id backend/models/grounding-dino-tiny \
  --sticker-score 0.22 --sticker-max-area-px 1000
```

增加 `--subtitle-strength conservative` 可恢复 26 版文字遮罩。
库调用对应 `process_video(..., subtitle_strength='conservative')`。
此参数仅影响 ProPainter，LAMA、OCR 调度与跨切景核验、ROI、贴纸检测和
12px 外扩均不变；模板补全、白字复修仍默认关闭。

本次增强针对字形边缘残留，不解决 OCR 框外的整段漏字。原片第 135 帧
重建的单帧 OCR 框只覆盖 `Non-slip`、`Sturdy` 的部分文字，相邻 9 个
关键帧的现有模板补全也未可靠补回这两个后缀，因此未将该实验自动启用。
此处使用的是本机重建遮罩，不是服务器生成 26 时的实际遮罩记录。

第 135 帧重建遮罩由 14,452 像素增加至 17,002 像素，新增 2,550 像素
约占整帧 0.28%，均位于原字形外围一圈；这不代表画质损失比例或擦净率。
普通回归 247 项通过、10 项条件跳过，覆盖默认值、保真回退、ROI 和
字间背景保护、贴纸范围不变、模型及合成接入。未运行新全片 CUDA 推理，
需检查 4-5 秒的笔画残留、裤腿和红鞋边缘，并对照 26 验收最终画质。

## 2026-09-10：25 的开头 emoji 漏罩修正

`test_pro_25_without_c.mp4` 开头的问题不在自动 ROI：
`(443, 1052, 0, 624)` 已覆盖三个 emoji。左侧 emoji 在部分采样帧得分
略低于 `--sticker-score 0.22`，旧关联又把单次漏检当作消失，造成前
90 帧中 44 帧缺框：7-14、22-28、30-35、60-82。缺罩既直接漏擦，
也会使 ProPainter 从邻帧传播尚未遮住的 emoji 像素。

本轮仅修改 GDINO 的候选检测、跟踪和遮罩接入：

- 新目标仍须达到用户设定的分数，保留低至 `min(0.15, sticker_score)`
  的候选供续跟；低分不能独立建轨，面积上限不变。
- 原片每帧仅做已知贴纸附近的局部外观检查；颜色与结构仍匹配时补齐
  遮罩，真消失时留空。参考不能跨切景，最长两秒；相邻 emoji 分别关联。
- 保留优先采样，剩余调用预算用于反馈补查：变化时加密，稳定后逐步
  退避。不逐帧调用 OCR 或 GDINO，失败调用也计入预算。
- 反馈命中可续接同目标两侧的轨迹；无效新参考不能挡住仍有效的旧参考，
  也不能延长旧参考寿命。零预算不加载贴纸模型。
- 确认后的逐帧框直接生成模型输入遮罩，不再经过旧插值；12 像素贴纸
  外扩、ROI、文字遮罩、模型窗口和 VLM 后端行为不变。

真实原片候选回放确认 44 帧缺口全部补齐：0-89 帧各有三个独立贴纸框，
90-99 帧贴纸消失后不再生成其遮罩。离线真实 GDINO 首帧检出三个框，
得分约为 0.3537、0.2583、0.2491。

另用真实 CPU ProPainter 权重对前 29 帧原尺寸 256 x 256 裁剪做对照，
只替换旧/新遮罩，不启用字形补全或复修。在左侧 emoji 原橙色位置统计：
第 0、7、14、15、22、28 帧的橙色残留由 70、101、101、72、101、101
像素降为各 0 像素；编码前有效遮罩外逐帧保持原图。这个指标只覆盖指定
颜色和局部区域，不代表所有残影消失，也不等于完整 CUDA 成片已验收。

最终普通回归 235 项通过、10 项条件跳过；单独启用原片贴纸回放后 2 项
通过，慢速真实模型对照另有 1 项通过。规格与代码质量审查均已完成。

## 2026-09-07：字幕残留修复试验

针对 `test_pro_16.mp4` 中白衣服上的半句、局部漏框和暗描边残留，
ProPainter 流水线增加以下处理，模型和反馈式 OCR 不变：

- 白字有效遮罩向外扩 2 像素，覆盖窄暗描边，仍不填满整行矩形。
- 60 帧范围内缓存有限的局部字形参考。只有文字内容和位置匹配才补全
  缺失字形或缩短的 OCR 框；无当前文字框、换句或过期时不盲目传播。
- 残留复核比较原片与结果的亮暗结构，包含暗笔画。选择复修片段前
  限制到可信有效遮罩；每个窗口最多一次局部二轮，失败保留首轮。
- 日志新增 `字形补全` 和 `疑似残留` 帧数，统计返回值对应
  `template_recovered` 和 `unresolved`。二轮次数不是擦净的证明。
  复核异常不阻止视频写出，另计 `复核未完成`（`residual_check_failed`），
  不能将这些帧当作通过验收。

## 2026-09-07：反馈式 OCR 流水线

当前 `vsr_pipeline.py` 默认全屏检测，稳定时 OCR 间隔按 `1 → 2 → 4 → 5`
帧递增，出现变化立即逐帧检测并回查跳过帧。`--ocr-stride` 调整最大间隔，
`--ocr-refine-radius` 限制回查深度。手动 `-c` 仍限定全部检测和遮罩范围。

```bash
python vsr_pipeline.py -i TikSave.io_7635080993354878239.mp4 \
  -o test_auto_dynamic.mp4 --inpaint-mode propainter \
  --ocr-stride 5 --vlm-max-calls 32
```

本机实际使用 PaddleOCR mobile 对该 720×1280 视频完成全屏检测：

| 指标 | 结果 |
| --- | --- |
| 解码帧数 | 687 |
| OCR 调用 | 428（主动采样 342，变化后补查 86） |
| 确认文字轨迹 | 37 |
| 丢弃的孤立命中 | 23 |
| 文字轨迹覆盖帧 | 598 |
| CPU 检测耗时 | 419.6 秒 |

OCR 调用比逐帧检测少约 38%。旧计划的 150–250 次只是预估，此视频变化较多，
未达到该区间；全屏检测耗时也不能与较小手动 ROI 的旧耗时直接对比。
这些数据只证明检测阶段可运行，不代表字幕/贴纸识别完全正确。

本地全量自动测试通过（77 项），覆盖真实 OpenCV 遮罩、PyAV 合成视频
解码/编码、反馈回查、贴纸邻近关联、VLM 请求失败降级、60 帧分段、
切景分段、单帧修复输入保护和局部复修失败降级。
修复模型在集成测试中使用替身，因此尚未验收 TikSave 的 0–2 秒贴纸清除、

## 二、总流程:三段式 + 一个闭环

```
第1步 截帧侦察(1分钟,决定后面所有选择)
  ↓
第2步 主处理:sttn-det 检测 + LAMA 修复 + 手动字幕区域(几分钟~半小时)
  ↓
第3步 验收:像素差分全片扫描(1~2分钟,确定性,不漏报)
  ↓ 有残留帧
第4步 补擦闭环:差分位置生成贴合 mask → LAMA 局部修复 → 拼回 → 再差分,直到归零
```

### 第 1 步:截帧侦察(永远第一步)

```python
# 从视频均匀抽 4~6 帧存 png,逐帧看:
# 1) 字幕在画面什么位置(顶部/中部/底部)?—— 决定 -c 区域坐标
# 2) 位置固定还是随镜头移动?        —— 决定选模式
# 3) 对比度高低(白字压浅背景=高危)? —— 预判 OCR 漏检风险
```

坐标格式:`-c YMIN YMAX XMIN XMAX`(先纵后横,可多次 `-c` 指定多区域)。**量坐标的方法**:截帧后用画图标注网格线(间隔 50px),对照读出文字的像素范围,四周各留 20~30px 余量。

### 第 2 步:主处理

```shell
python backend/main.py -i 输入.mp4 -o test/输出.mp4 \
    -c 450 1010 0 720 \
    --inpaint-mode lama
```

**决策表(实测依据):**

| 场景 | 做法 | 依据 |
|---|---|---|
| 通用主处理 | `sttn-det` 或 `lama` 模式 + 手动 `-c` 区域 | 只擦检测到的文字,不伤画面主体 |
| 静态、单一位置字幕 | `sttn-auto` + 固定框,一步搞定 | 不做检测直接重绘;但框内必须是"非文字即纯背景"(先截帧确认),否则误伤主体 |
| 动态/多位置字幕 | 必须走检测模式 | 固定框框不住移动的字幕 |
| 检测模型 | 保持 `PP_OCRv5_MOBILE`(config.json) | 比 Server 快 14 倍(3.5 vs 50 分钟/687帧);漏检的交给第 4 步兜底 |

**为什么修复选 LAMA 而不是 STTN/ProPainter(实测):**

| 模式 | 实测结果(687帧竖屏) |
|---|---|
| **LAMA** | **31 分钟,修复区锐利接近原图** ✅ |
| STTN(det) | 72 分钟,修复区发糊(条带压缩到 432×240 再放大,细节不可逆损失) |
| ProPainter | 18 分钟(3秒片段),同套检测照样漏检 + 光流拖影形变,已弃用 |

关键认知:**瓶颈在检测不在修复。** 所有修复模型共用同一套 OCR mask,OCR 检不到的字谁也擦不掉。换修复模型解决不了漏检。

### 第 3 步:验收——像素差分(不要跳过!)

去字幕任务自带"标准答案":原视频哪里有字是已知的。逐像素对照原视频和成品,**"原视频有字 + 成品仍是字" = 漏擦**,这是确定性推理,不依赖任何模型、不会漏报。

```python
# 核心判据(拿正反例帧校准后的版本)
# 窗口 = 字幕活动区域
wo = (w[:,:,0]>228) & (w[:,:,1]>228) & (w[:,:,2]>228) & (abs(w[:,:,0]-w[:,:,2])<25)  # 原视频白字
wv = (v[:,:,0]>210) & (v[:,:,1]>210) & (v[:,:,2]>210) & (abs(v[:,:,0]-v[:,:,2])<25)  # 成品仍白
resid = wo & wv    # 两者同时成立 = 残留像素
```

**三个必须注意的坑:**

1. **阈值必须校准,不能拍脑袋。** 拿一帧确认有残留的(正例)和一帧确认干净的(反例)跑同一判据:正例报得出、反例归零,阈值才可信。第一版判据(只看亮度)曾把牛仔裤裤腿全误报成"每帧都有残留"。
2. **`|R−B|<25` 是排除彩色亮物的关键**(白字 R≈G≈B;蓝裤腿 B 比 R 高 15+)。窗口里有浅色衣物/白墙时尤其重要。
3. 差分管"有没有漏擦",不管"擦得好不好看"——画质验收另需截帧肉眼确认。两者互补。
4. **差分报警 ≠ 残留,必须肉眼复核**:白字压浅色地面场景有本质歧义——字擦掉后重建出的地面本身就近白,会被判据误报。差分的正确用法是"报警帧列表 → 逐帧肉眼裁决",报警量异常增大时优先怀疑误报。

### 第 4 步:补擦闭环

差分报告精确到"帧 + 残留像素位置",照单抓药:

```python
# 1) mask = 原视频白字字形(wo)填入全帧零图,膨胀 21×21 核(约10px)
#    —— 用原视频字形做 mask,贴合到笔画级、零幻觉、不误伤
# 2) LAMA 局部修复该帧(单帧几秒,模型只加载一次)
# 3) 帧级替换拼回:av 逐帧重编码 crf18,仅替换目标帧;ffmpeg -map 0:v -map 1:a -c copy 合回音频
# 4) 再跑差分复扫 → 归零才收工;仍有残留就再来一轮(每轮成本几十秒)
```

要点:
- **只修差分报出的帧,不需要为"连续性"扩大范围**——LAMA 是单帧修复、帧间无依赖;其余帧在主处理时已擦干净
- 修完**必须复扫差分**,闭环归零才算数(实测第一轮 VLM 补擦就漏了 6 帧)
- 差分若报出**一大段连续帧**,说明主流程整段漏擦,应回头查 `-c` 区域/检测参数,而不是逐帧补

## 三、关于用 VLM(如 qwen-vl)辅助

实测结论(DashScope qwen3.7-plus):

| 用法 | 实测效果 |
|---|---|
| 逐帧 grounding 定位残留 | **可用**:淡灰残迹 160/171 帧稳定检出;但框偶尔不完整(导致 v3 漏 6 帧),且同帧两次调用结果可能不同 |
| 视频级定位(帧序列一次调用) | **不能当主定位**:主残留(3~8.6s 几乎每帧)只报出一个 0.5s 小区间,漏报严重 |
| 验收 | **不能用 VLM 验收,必须用像素差分**(确定性、零成本、不漏报) |

合理分工:**VLM 做"发现"(省人工盯帧),差分做"验收"**。坐标注意:qwen-vl 返回的 `bbox_2d` 是 0-1000 归一化坐标,需乘实际宽高换算。扫描策略:先稀疏(每 5~10 帧)锁定残留时间区间,区间内再逐帧;不要拍脑袋抽 15 帧(翻车过:6 秒处漏网被用户发现)。

对外服务若接 VLM API,注意**帧数据出域**需客户/合规确认。

## 五、一句话流程

> **截帧看清 → LAMA + Mobile OCR + 手动区域 → 差分验收归零 → 漏的用字形 mask 补擦。**
> 任何环节不确定,就截帧看;阈值不确定,就拿正反例帧校准。

## 六、踩坑清单(速查)

- `-o` 输出路径不带目录 → `os.makedirs('')` 报错;**永远带目录**
- 全屏自动检测偏向底部常规字幕;顶部/中部字幕必须手动 `-c`
- 多个不同修复模型残留位置完全相同 → OCR 漏检,换修复模型无用
- 低对比度白字(白字压浅地面)是 OCR 系统性盲区,Mobile/Precise 都漏 → 差分 + 字形 mask 补擦兜底
- 差分窗口含浅色衣物/白墙 → 必须用 `|R−B|<25` 白字判据并先校准
- CPU 上试错很贵(每遍 30~70 分钟):跑之前先截帧+裁剪把坐标参数想清楚
