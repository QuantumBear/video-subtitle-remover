# SAM3 文字＋DINO emoji 试跑

两个根目录脚本现在默认使用 **SAM3 文字 mask＋DINO 稀疏 emoji 检测**。不加载 PaddleOCR 或 VLM，不再运行第二遍 SAM3 视频 emoji 推理。纯 STTN 为主，第二个脚本保留有限 ProPainter 残留补修。

```bash
./run_sttn.sh input1.mp4 output_sam3_sttn.mp4
./run_sttn_propainter.sh input1.mp4 output_sam3_sttn_propainter.mp4
```

文字沿用已验证配置：SAM3 `caption`、主阈值0.5、原图轮廓外扩3px；只有文字主阈值 mask 整帧为空才采用同次推理的0.3候选。DINO 不改变文字轮廓或孔洞，只把接受的 emoji 框外扩12px并入该帧 mask，裁剪到手工 ROI；STTN 调度、合成与 ProPainter 补修使用同一份合并后的 mask。

DINO 默认本地 `backend/models/grounding-dino-tiny`、FP16、batch4、提示 `emoji. sticker. cartoon icon.`、强候选阈值0.22、原视频框面积上限1200px²。每个检测帧按当前文字 mask 外接框向四边扩框高两倍，无文字则使用 ROI。裁剪帮助小目标召回，会遗漏远离文字的图形，不是全画面任意贴纸检测保证。

优先检测每秒网格、自动切镜、开头两秒的半秒网格和末帧，再用原反馈补查；全片最多200个检测帧次，失败也计入预算。跳过检测的帧进行局部外观核验，弱候选只能续接已有目标，不创建新目标。外观核验不能证明目标是后期叠加物；多次强命中同样可能误选实体。

SAM3 图像模型、DINO、STTN 依次加载和释放，不同时保留两套检测模型。省去 SAM3 视频分支的逐帧跟踪状态，但异形裁剪混批可能因 padding 增加 DINO 临时显存；不能仅凭模型大小推算峰值或服务 slots。STTN 常驻复用、多进程并发时也需单独测量。

第二个脚本全片最多8个 ProPainter窗口，每窗最多30帧（包含上下文）；只处理疑似残留窗口，不补回 mask 漏掉的目标。

## 环境与调整

DGX 优先复用 `quality_eval_20261109/sam3_mask_compare/env/bin/python`、`sam3_code` 和 `sam3_model/sam3.pt`，DINO 使用项目内本地权重，不在启动时安装依赖或下载模型。其它机器可设置：

```bash
export SAM3_PYTHON=/path/to/env/bin/python
export SAM3_CODE_DIR=/path/to/official-sam3
export SAM3_CHECKPOINT=/path/to/sam3.pt
export STICKER_MODEL_ID=/path/to/grounding-dino-tiny
./run_sttn.sh input.mp4 output.mp4
```

无实验目录时使用当前 `python`、`backend/models/sam3/code`、`backend/models/sam3/sam3.pt`。环境需要官方 SAM3、Transformers/DINO 和流水线依赖；权重仍适用各自许可证。

```bash
# 关闭 DINO，回到仅 SAM3 caption：
./run_sttn.sh input1.mp4 output_caption_only.mp4 --no-locate-stickers
# 记录检测分阶段耗时与显存：
./run_sttn.sh input1.mp4 output_profile.mp4 --sttn-profile --sticker-profile
# 调整调用预算或 batch（批次减小可缓解混合尺寸 padding 的峰值）：
STICKER_MAX_FRAMES=100 STICKER_BATCH_SIZE=2 ./run_sttn.sh input1.mp4 output_dino.mp4
# 回退文字外扩与空帧候选：
SAM3_DILATE=0 SAM3_EMPTY_SCORE=0 ./run_sttn.sh input1.mp4 output_baseline.mp4 --no-locate-stickers
```

DINO 可调环境变量为 `STICKER_MODEL_ID`、`STICKER_PROMPT`、`STICKER_SCORE`、`STICKER_MAX_AREA_PX`、`STICKER_MAX_FRAMES`、`STICKER_BATCH_SIZE`。额外 CLI 参数放两个视频路径后，会覆盖脚本中的同名设置。面积和外扩都是原视频像素配置，不保证跨分辨率最优。

文字可调 `SAM3_SCORE`、`SAM3_DILATE`、`SAM3_EMPTY_SCORE`。空帧候选不得高于主阈值；它不解决已有非空 mask 中的部分漏检。自定义提示可多次传 `--sam3-prompt`，显式提示会替代默认 `caption`。

此前 SAM3 视频 emoji 路径保留作显式对照，`SAM3_EMOJI_SCORE`默认0。设为正数会选用视频 emoji、自动跳过 DINO，避免两套 emoji 推理叠加；默认连续三帧确认，`SAM3_EMOJI_MAX_FRAMES`默认120。该可选路径仍需CUDA与Triton所需Python开发头文件，DGX复用已有头文件。

```bash
SAM3_EMOJI_SCORE=0.3 ./run_sttn.sh input1.mp4 output_sam3_video_emoji.mp4
```

直接使用 Python API / CLI 时默认仍为旧检测后端。显式 `--mask-backend sam3 --sticker-backend gdino` 才启用组合；SAM3 下 VLM 不运行。调用组合的完整 CLI 配置：

```bash
python vsr_pipeline.py -i input.mp4 -o output.mp4 \
  --device cuda --inpaint-mode sttn --sttn-precision fp16 \
  --mask-backend sam3 --sam3-score 0.5 --sam3-dilate 3 --sam3-empty-score 0.3 \
  --sticker-backend gdino --sticker-model-id backend/models/grounding-dino-tiny \
  --sticker-prompt 'emoji. sticker. cartoon icon.' --sticker-score 0.22 \
  --sticker-max-area-px 1200 --sticker-max-frames 200 --threads 1
```

mask 以无损 PNG 暂存于系统临时目录，正常或异常退出清理；强杀进程可能遗留 `vsr-sam3-*`。显式请求组合时，DINO 初始化或合并失败会报错，不静默产出“已完成 emoji 去除”的结果；逐帧检测失败仍由既有跟踪器计数并打印，最终统计 `gdino_emoji_model_failed` 可查看。`gdino_emoji_frames`、`gdino_emoji_added_pixels` 记录新增支持，`gdino_emoji_calls`记录实际检测帧次，不等于正确率。

## 已知画质限制

先前同片实验的 DINO 71次检测＋跟踪约20.20秒、加载约6.58秒，已核验emoji框270/270匹配；但戒指被误选7帧。只用 `emoji.` 提示的新对照反而增加实体候选，约35.06秒、150次调用，戒指仍被选中，因此不采用该提示。

**戒指误擦尚未解决。** 本次按速度取舍启用已验证的通用提示，不把外观关联宣称为语义内容核验。新视频仍须检查实体误擦、漏emoji与切镜闪烁；可用 `--no-locate-stickers` 做对照。完整实验见 [SAM3与DINO补漏评估](../07-dev/21-SAM3与DINO补漏评估.md)。补全遮罩也不代表 STTN 能恢复结构纹理，3秒附近金属、网格和台阶等区域仍可能涂抹。
